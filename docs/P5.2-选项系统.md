## 2. 全局选项（MXU setting 扩展）设计

MaaFramework 的 `interface.json` 支持顶层 `setting`（设置段）与 `global_option`（全局选项键列表）。MXU 原清单两者都未使用（P3.6 遗留项）。本次把它做成一条**可用的数据/编译层**，同时兼容未来 MXU 补齐 setting。

**语义**

- **作用域**：全局选项属于「配置组」（`TaskConfiguration.GlobalOptions`），对本组所有任务生效；切换配置组即切换整套全局值。
- **来源**：`setting[].option`（含分组标题/描述）∪ `global_option`（扁平键列表），去重后由 `InterfaceConfig.GlobalOptionKeys()` 给出，顺序 = 定义顺序。
- **优先级**：任务级 > 全局级。编译每个任务时先合并全局层、再叠任务层，同名节点按**字段**递归合并，因此任务级同名选项覆盖全局值；任务级「默认值」同样视为任务级取值（与 P3.4 一致）。
- **存储编码**：与任务级完全相同（select/switch=case 名；checkbox=`,` 连接；input=`选项/字段`），复用 `TaskOptions` 的一处约定，不重复定义。

**数据流**

```
interface.json (setting + global_option + option)
        │  Load / 合并
        ▼
InterfaceConfig.GlobalOptionKeys()  ──►  UI「全局选项」页按 setting 段渲染
        │                                     │ 编辑
        │                                     ▼
        │                          TaskConfiguration.GlobalOptions  ──落盘──► config/maayys.json
        ▼
TaskOptions.Compile(config, task, taskValues, globalValues)  ──►  pipeline_override（P5.3 投递）
```

## 5. 遗留（交给后续）

- **运行时兑现**：全局/任务选项编译出的 `pipeline_override` 目前只做「预览 + 契约」。真正投递到 `MaaTaskerPostTask` 在 **P5.3 执行引擎** 完成，届时「改选项后重跑行为符合预期」得到端到端验证。
- **setting 面板深入**：`SettingSectionConfig.DefaultExpand`（默认展开）暂未参与 UI；设置项数量增多后可加折叠。
- **全局选项的「真正生效」**：本次示例全局选项编译到命名空间节点，用于演示合并链路；若要对真实 pipeline 生效，需由 agent/引擎读取或在 pipeline 侧引用对应参数（部分属 P5.3 / P7 范畴）。
