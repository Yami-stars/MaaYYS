## 4. 压缩与去重（结论：没有收益）

| 检查 | 结果 |
|---|---|
| 内容完全相同（md5）的组 | **仅 1 组 2 张**（`自动御魂/自动御魂2.png` 与 `自动御魂2_1.png`） |
| 分辨率种类 | 403 种，绝大多数是小图标（最常见 60×51 等） |
| >200 KB 的图 | 3 张，最大 323 KB（`自动业原火/业原火-点击业原火_1.png`） |

**不去重、不压缩**：435 张加起来才 6.9 MB，重复只有 1 组，压缩收益接近 0，
反而会引入「改了图但 pipeline 引用的还是旧文件」这类风险。

## 5. 交付与结论

| 验收项 | 结果 |
|---|---|
| 710 张模板图迁移 | ✅ 全量迁入，0 漏项 |
| `任务名/节点名_序号.png` 命名规范 | ✅ 主体符合；1 个散落文件 + 6 个空目录登记不处理 |
| 压缩去重 | ✅ 已评估：收益 ~0，**不做** |
| template 引用 100% 有对应文件 | ✅ **604 处 / 431 张，缺失 0** |

**后续约定**

1. 新增模板图必须放 `image/<模块>/` 下，文件名用节点名；引用时写完整相对路径。
2. 不要手工删图——「没有任何节点引用的图」由版本更新时的自动整理处理
   （`probe audit` / 设置页「资源整理」），它按「8 个资源集取交集」判定，不会误删渠道服还在用的图。
3. 截图命名由编辑器自动生成时容易带上 ROI 坐标，生成后要手工改回节点名。
