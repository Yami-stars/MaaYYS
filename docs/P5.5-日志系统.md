## 二、引擎层新增（`src/MaaYys.Engine/Logging/`，无 UI 依赖）

| 文件 | 作用 |
|---|---|
| `LogLevel.cs` | 级别枚举 + 文本互转（宽松解析 `DEBUG`/`[WARN]`/`ERR` 等写法） |
| `LogEntry.cs` | 日志条目 + `LogThumbnail`（原始像素缩略图）+ `ILogSink` + 写入语法糖 + `ScopedLogSink`（多实例打标签） |
| `LogOptions.cs` | 策略：时间格式、容量、节点事件开关、截图尺寸/上限；`Sanitized()` 夹取非法值 |
| `LogBuffer.cs` | 环形缓冲：头指针淘汰 + 批量压实（追加 O(1)）、序号单调、增量/过滤查询、截图上限与淘汰回收 |
| `FrameworkLogTranslator.cs` | 原生事件 → 中文正文（`Tasker.Task.Failed` → 「任务 #7 失败：自动御魂」），节点级事件按开关过滤 |
| `EngineLogPipeline.cs` | 管线：原生事件 / agent 输出 / 引擎自身日志统一入口，警告以上自动附图 |
| `ThumbnailFactory.cs` | 帧 → 缩略图（块平均；不放大；通道不支持返回 null） |
| `LogExporter.cs` | 文本 / CSV 格式化 + 截图文件名约定（`FormatLine` / `ToText` / `ToCsv` / `Escape`） |

**引擎接线**（`MaaYysEngine`）：`Log` 管线属性；`Tasker.*`/`Resource.*` 事件、连接/资源加载/停止/释放、agent 启动结果全部落日志。为 null 时不产生任何开销（探针/测试默认即此状态）。

**agent 输出捕获**（`MaaAgentSession`）：`RedirectStandardOutput/Error = true` + `BeginOutputReadLine()`（异步读，管道写满不会阻塞子进程），握手成功后才开始读——之前产生的输出仍留在系统管道里，启动阶段日志也不会丢。

## 三、应用层

- `InstanceWorkspace.Log`：全程序唯一 `LogBuffer`（容量/格式取自配置），各实例引擎用 `ScopedLogSink` 打上实例名写入同一流。
- `InstanceViewModel`：建引擎时挂 `EngineLogPipeline`；截图来源是**最近一帧缓存**（帧回调里只换引用，错误发生时才缩放）——不在框架回调线程里现抓图，避免任务执行中重入控制器。
- `QueueRunService`：队列开始/逐项 Running·Done·Failed·Skipped·Stopped/整轮汇总；`TimerRunner`：到点、跳过、强制启动、失败全部落日志。
- 日志页（导航第 4 项）：级别/来源/关键字过滤、时间格式、自动滚动、暂停刷新、节点级事件开关、复制、导出、清空；截图卡片点击打开 `LogImageView`（另存 PNG）。

## 五、性能设计（"长跑 2h 不卡顿"怎么保证）

1. **写入端**：环形缓冲容量固定（默认 2 万），淘汰用头指针 + 批量压实，追加是 O(1)；截图设上限（默认 300 张），超限只丢图不丢日志。
2. **界面端**：不逐条订阅，200ms 轮询 `Version`——无变化时零开销；积压 >300 条时整体重建而非逐条插入。
3. **渲染端**：界面只保留最近 2000 行，`VirtualizingPanel.IsVirtualizing + Recycling`，滚动不重建容器。
4. **自动滚动**：批量追加后只 `ScrollIntoView` 一次（逐条滚动会触发几十次布局）。

## 六、顺带修掉的一个渲染问题

WPF 默认 `CheckBox` 模板的 `ContentPresenter` 不继承窗口前景色，暗色主题下把标签画成黑字——日志页的面板扫描发现"只有白方块、标签看不见"。已在 `Theme.Dark.xaml` / `Theme.Light.xaml` 各加一条隐式 `CheckBox` 样式（前景色 + 垂直居中），**影响全应用所有勾选框**（定时页星期选择、任务页启用等同样受益）。
