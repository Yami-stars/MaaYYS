## 2. 为什么不是「删 debug.json + test.json」那么简单

流程表原计划把 `debug.json` 和 `test.json` 一起剔除。实际测量推翻了这一条：

**`debug.json` 是全局错误处理的载体，删了会让每个节点都引用悬空。**

```jsonc
// resource_pack/base/default_pipeline.json
{
    "Default": {
        "pre_delay": 200,
        "post_delay": 1000,
        "on_error": ["[JumpBack]悬赏封印_协助战斗1"]   // ← 对「所有节点」生效
    }
}
```

`悬赏封印_协助战斗1` → `悬赏封印_拒绝邀请` / `确定关闭悬赏封印协助` 全部定义在 `debug.json` 里。
用框架的 `MaaResourceGetNodeData` 读任意节点的最终定义，都能看到这条兜底边：

```
[节点] 启动游戏 = {
  "next": [{"name": "启动游戏-跳过动画"}],
  "on_error": [{"name": "悬赏封印_协助战斗1", "jump_back": true}],   ← 来自 default_pipeline.json
  "post_delay": 1000,
  ...
}
```

**`test.json` 才是真垃圾**：16 个节点全部不可达，且节点名（`N-1766075283687`、`testAction`、`测试-停止任务`）
在 `agent.exe` 二进制里一次都没出现（`grep -c` = 0），删掉不影响任何一侧。已删除，原文件在
`D:\YYS\MaaYYs-win32-win-x86_64-v3.13.6-2608192116-MXU\resource_pack\base\pipeline\test.json`。

## 3. 三个必须记住的框架语义（都已实测确认）

### 3.1 跨 bundle 是「字段级」合并，不是整节点替换

`official/pipeline/启动游戏.json` 只写了 `package`：

```jsonc
{ "启动游戏": { "package": "com.netease.onmyoji.wyzymnqsd_cps" } }
```

如果按「整节点替换」理解，base 的 `recognition` / `next` 会全部丢失、启动链路直接断掉。
实测 `GetNodeData` 显示 `next` 仍然存在 → **框架按字段合并，渠道层只覆盖它写了的字段**。

> 这条直接决定 P3.5（渠道服分层重构）的做法：渠道包只需要写差异字段，不必复制整个节点。

### 3.2 `pipeline_override` 的键是节点名，也是「活节点」的来源

`tasks/*.json` 的 `option[].cases[].pipeline_override` 键名是被覆盖的节点，
值里还可能含 `next` / `on_error` 指向别的节点。本次统计：**123 个覆盖目标 + 5 处覆盖内引用**。
只看 pipeline 内部引用会把它们误判成死节点。

### 3.3 可达性 ≠ 有入度

`test.json` 的 `N-1766075283687` 确实被 `测试-停止任务` 引用，但后者自己就是死的，整条链永远走不到。
所以判定必须从「任务入口 + 覆盖目标」做**可达性遍历**（含 `[Anchor]` 锚点解析），迭代到不动点。
实现见 `PipelineInventory.ComputeLiveNodes`。

## 5. 445 个不可达节点的构成

节点总数 1511，从 29 个任务入口可达 1066，**不可达 445（29.5%）**。
按文件归组后分三类：

### 5.1 未接线但可用的玩法（72 个节点，不应删除）

`interface.json` 只 import 了 **29 / 32** 个任务文件。未导入的 3 个任务对应的 pipeline 因此全部不可达：

| 未导入的 tasks 文件 | 任务名 | 入口节点 | 涉及节点 |
|---|---|---|---|
| `tasks/限时活动.json` | 限时活动 | `限时活动-泛舟争流` | 39（`活动/限定/限时活动-泛舟争流.json` 整份） |
| `tasks/活动-小超鬼王.json` | 活动爬塔-武道大会-修行合训 | 同名 | 15 |
| `tasks/自动业原火.json` | 自动业原火 | `业原火-开始业原火` | 15 |

实验验证：把 3 个文件补进 import 后，可达节点 **1039 → 1111（+72）**，三份 pipeline 全部复活。
→ **这不是垃圾，是没接线的功能。是否开放由产品决定（见 §8）。**

### 5.2 月度活动轮换包（约 100 个节点，不应删除）

`活动/每月周期/` 下有 9 份「活动300-*」包，对应每月轮换一个的爬塔活动。
当前只接了 `活动爬塔-云华依言歌`，其余 8 份（夜见前事 / 归狐谣 / 执火燎原 / 月自长梦升 / 洪狐天运 /
跪夜百戏 / 醒世达观 / 金砂福威）+ `活动300.json` 通用层全部不可达。
游戏每期换活动，这些包**留着下期直接切换**，删掉下次就得从原始包找回来。

## 7. 命名规范现状

58 个节点（3.8%）命名不规范，三类：

| 类型 | 例子 | 数量级 |
|---|---|---|
| 编辑器自动生成 | `N-1766075283687`、`N-1776821607427` | 11 |
| 拖拽复制 | `寮3039_copy1_copy1`、`9997_copy1` | 45 |
| 一次性测试 | `testOCR`、`testAction` | 2（随 `test.json` 一起删掉了大部分） |

**不做批量改名**：改一个节点名要同步改所有 `next` / `on_error` / `pipeline_override` 里的引用
（本次统计有 800+ 处 `next` 引用），一旦漏改就是运行期静默断链。
约定往后**新增**节点用 `<玩法>-<动作>` 形式（如 `月活动-点击开始挑战`），存量不追。
