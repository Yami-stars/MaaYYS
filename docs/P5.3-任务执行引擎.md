# P5.3 任务执行引擎验收（2026-10-27）

> 目标（流程表 5.3）：启动/停止/暂停；异步状态回调；任务超时（对标 MAA StallTimeout）；失败重试策略；运行时长上限。
> 验收标准：**可随时停止且状态一致；超时正确触发**。

## 一、结论

| 验收项 | 结果 |
|---|---|
| 启动 / 停止 | ✅ 队列按顺序投递；停止会中止当前任务并**不再执行后续项**，终态统一为 `Stopped` |
| 暂停 / 继续 | ✅ 暂停 = 中止当前任务并记住下标，继续时**从该任务重新开始**（框架不支持冻结进程内任务） |
| 异步状态回调 | ✅ `ItemStatusChanged` / `StateChanged` 双事件；UI 侧统一切回 UI 线程后驱动色条 |
| 停滞超时 | ✅ 无框架事件超过 `StallTimeoutSeconds`（默认 60s）即中止并判失败，**不重试**（重试必然再次卡死） |
| 失败重试 | ✅ `MaxRetries` + `RetryDelayMs`；重试次数耗尽后按 `StopOnFailure` 决定是否停队列 |
| 运行时长上限 | ✅ `MaxDurationSeconds` 到点中止；**即使一直有进展也算超时长** |
| 「从此处运行」 | ✅ 右键菜单 → 从该下标开始执行 |
| 状态一致性 | ✅ 停止/暂停后 `State` 必回到 `Idle` 或 `Paused`，不会卡在 `Stopping` |
| 测试 / 构建 | ✅ **209/209**（新增 19 例：执行器 12 + 执行计划 5 + 真实引擎集成 2）；0 警告 0 错误 |

## 二、交付物

新增 `src/MaaYys.Engine/Execution/`（引擎层，无 UI / 无原生句柄依赖，可单测）：

| 文件 | 职责 |
|---|---|
| `ExecutionOptions.cs` | 策略（停滞超时 / 重试 / 时长上限 / 失败即停）+ `ExecutionState` / `ExecutionOutcome` / `ExecutionItem` / `ExecutionSummary` / 状态事件参数 |
| `IExecutionHost.cs` | 宿主抽象：`IsReady` / `Activity` / `RunTaskAsync` / `Stop` |

| `QueueExecutor.cs` | 执行核心：顺序投递、暂停/停止、重试、停滞看门狗、时长上限 |
| `ExecutionPlan.cs` | 队列项 → (entry, `pipeline_override`) 的编译契约（任务级 + 全局选项合并） |

界面接线（`TasksViewModel` / `TasksView.xaml`）：

- 左栏新增运行控制条：**开始运行 / 暂停·继续 / 停止** + 右侧状态文案（空闲 / 运行中 / 停止中 / 已暂停）。
- `RunFromHere` 由占位提示改为真实调度（从该下标开始）。
- `SetStatus` 由执行事件驱动，队列项左侧色条按 `Pending/Running/Done/Skipped/Failed/Stopped` 实时变化。
- 执行器按引擎实例缓存，实例切换/重连自动重建宿主；页面 `Dispose` 释放订阅。

## 三、关键语义（与 MAA 对齐 + 差异说明）

1. **暂停是「中止 + 记录位置」而非冻结**：MaaFramework 没有暂停原语，只能 `PostStop` 后重投。所以「继续」会让当前任务从头跑一次——这与 MAA 的暂停行为一致，但要在 UI 上让用户预期正确（暂停后色条是橙色 `Stopped`，不是运行中）。
2. **停滞超时用「任一框架事件」作心跳**，不只 `Tasker.Task.*`：节点级事件（`Tasker.Task.Node.*`）才是真实进展信号；只看任务级事件会在长任务里误判。
3. **停滞与超时长都判「失败」且不重试**（`fatal`）：这两类问题重试必然复现，重试只会拖长卡死时间。普通失败（引擎返回 Failed）才走重试。
4. **失败默认停队列**（`StopOnFailure = true`，MAA 行为）；需要「失败继续」时置 false。
5. **投递入口用 task 名**，与 `interface.json` 的 `task[].entry` 约定一致；找不到任务定义时不阻断执行，退化为投递默认 pipeline（`pipeline_override = null`）。


- `QueueExecutorTests`（12 例，假宿主）：顺序执行 / 跳过禁用 / 重试至成功 / 失败即停 / 失败继续 / 运行中停止 / 暂停后恢复 / 停滞超时 / 活动重置心跳 / 时长上限 / 宿主未就绪 / 重复启动拒绝。
- `ExecutionPlanTests`（5 例，真实 `resource/interface.json`）：字段映射、别名与禁用、未知任务降级、同类多实例保序、全局选项层真的进入 override。
- `ExecutionIntegrationTests`（2 例，**真引擎 + Null 控制器 + test_resource**）：队列跑通两任务全 `Done`；不存在的入口快速失败不挂死（60s 上限内返回）。

界面冒烟：`MaaYys.exe --page 1 --screenshot` 渲染正常，三个按钮排布无裁切、队列为空时「开始运行」正确置灰。

## 五、遗留

- **策略参数尚未暴露到设置页**：目前走 `ExecutionOptions` 默认值（60s 停滞、不重试、失败即停）。设置项归 P6.2「运行设置」。
- **真机长跑未验证**：停滞超时的真实触发需要接阴阳师窗口跑一个会卡住的任务；当前用假宿主 + 注入时钟做了确定性验证。
- **暂停粒度为任务**：不支持「暂停在当前任务中途、继续时从中间那个节点续跑」。
- **无队列级总时长上限**：只有单任务时长上限；如需「整轮不超过 N 小时」留待 P5.4 定时任务一起做。
