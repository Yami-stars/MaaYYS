## 2. 取值是怎么存的

`TaskSelection.Options` 是 `string → string`，所以先定死编码方式（这是**唯一**的约定，别在别处再发明一套）：

| 类型 | 存储键 | 存储值 | 例子 |
|---|---|---|---|
| `select` / `switch` | 选项名 | 选中的 case 名 | `"御魂挑战目标": "业原火"` |
| `checkbox` | 选项名 | 多个 case 名用 `,` 连接 | `"购买特殊商店物品": "御灵之钥,百物式盘"` |
| `input` | `选项名/字段名` | 用户填的字符串 | `"自动挑战次数/挑战次数": "25"` |

**未设置 = 用默认值**（`default_case` / `inputs[].default`），不在配置里存默认值。
好处：资源更新新增选项时旧配置自动拿到默认值，不会因为缺字段而失效；导入别人的配置也不会带一堆冗余默认值。

## 3. 编译规则（P5 直接复用）

`TaskOptions.Compile(config, task, values)` 产出 <c>pipeline_override</c> JSON，合并顺序：

1. `task[].pipeline_override`（任务级固定覆盖）
2. 各选项自身的 `pipeline_override`（`input` 类型靠它注入占位符）
3. 选中 case 的 `pipeline_override`

**同名节点按字段深合并**，数组整体替换——和框架的多 bundle 合并语义一致
（P3.1 §3.1 实测过：后加载者只覆盖它写了的字段）。

三条容易踩的细节：

- **联动子选项**：只有被选中的 case 才会带出 `case.option` 里的子选项。`自动御魂` 选「大蛇」→ 层数选项是 `悲鸣/拾层/神罚…`，改选「业原火」→ 层数选项变成 `痴之阵/嗔之阵/贪之阵`。
- **占位符 `{name}`**：整串就是一个占位符时**保留类型**（`"expected_number": "{n}"` → `10` 数字，不是 `"10"` 字符串）；字符串内插则按文本替换（`"note": "共{n}次"` → `"共10次"`）。
- **类型转换**按 `inputs[].pipeline_type`：`int` → 数字、`bool` → 布尔、其它 → 字符串。转不动时**不阻断**，回落成字符串并给出警告（界面上标 ⚠）。

## 4. 界面

任务页（左侧导航「任务」）：

- **左**：配置组下拉 + 29 个任务（勾选 = 加入任务队列，与实例页同一份数据；点任务名编辑参数）
- **右**：参数面板（按选项定义动态生成，嵌套项自动缩进）+ 底部「编译后的 `pipeline_override`」预览

预览不是装饰：它是 P5 投递 <c>MaaTaskerPostTask</c> 时**真正要传的那份 JSON**，调试识别/覆盖问题时看这里最快。

`select` / `switch` 若没有 `default_case`，默认是「无覆盖」状态，界面显示「（未选择，按默认处理）」——不是控件坏了。

### 实测（自动御魂）

改三处：目标 `八岐大蛇 → 业原火`、层数自动切到 `痴之阵` 后改成 `嗔之阵`、次数 `25`。
重启程序后三处取值全部保持，编译结果：

```jsonc
{
  "自动御魂_点击目标副本": { "expected": "业原火" },
  "自动御魂_点击目标层数": { "expected": "嗔之阵" },
  "自动御魂-开始装备御魂": { "enabled": true },
  "自动御魂_装备挑战御魂副本御魂": { "custom_action_param": { "group_name": "默认分组", "team_name": "默认队伍" } },
  "自动御魂-开始挂樱饼挑战": { "enable": true },
  "自动御魂-设置次数": { "custom_action_param": { "expected_number": 25, "start_repeat": true } },
  "自动御魂-识别次数": { "custom_recognition_param": { "target_count": 25 } }
}
```

`config/maayys.json` 里只留了改动过的三项（默认值不入库）：

```json
"tasks": [{
  "name": "自动御魂",
  "enabled": true,
  "options": {
    "御魂挑战目标": "业原火",
    "业原火挑战层数": "嗔之阵",
    "自动挑战次数/挑战次数": "25"
  }
}]
```

## 5. 与三个隐藏任务的关系

任务页只渲染 **`interface.json` 已 import 的 29 个**任务。三个隐藏任务（限时活动 / 活动爬塔-武道大会-修行合训 / 自动业原火）
没有 import，所以不出现——**这是刻意的**：它们的节点已被数据清理列为受保护，界面也不给用户「点了却跑不了」的错觉。
等以后加回 import，它们的参数面板会自动出现，不需要改代码。

## 6. 数据侧的两个发现

1. **19 个选项定义了但没有任何任务引用**（`probe tasks` 会列出来），包括 5 个 `checkbox`（`购买特殊商店物品`…）
   和若干 `input`（`组队副本-金额加成预设`、`御灵点击策略设置` 等）。这是上游的历史残留：早版本用 checkbox 勾选购买清单，
   后来改成 switch 就不用了。**不影响渲染**，也没清（删了要动 `tasks/*.json`，收益为零）。
2. `困28.json` 里两个选项的 `label` 都叫「困28阵容预设」（不同 key、不同字段数量），界面上看是两个同名输入框。
   属于资源侧命名问题，本阶段不做改名。
