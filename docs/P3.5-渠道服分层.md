# P3.5 渠道服分层重构报告

日期：2026-10-26 ｜ 基准：MaaYYs MXU v3.13.6 ｜ 测试：155/155

## 1. 分层契约（重构后的规则）

`interface.json` 的 `resource[].path` 是**有序**的：第一个 bundle 永远是 `base`（完整定义），
后面的每一个都是「渠道层」——**只写与 base 的差异字段**。MaaFramework 合并是字段级的
（P3.1 用 `MaaResourceGetNodeData` 实测确认），渠道层写一个字段就只覆盖那一个字段。

渠道层的三类合法内容：

| 类型 | 例子 | 说明 |
|---|---|---|
| `package` | `启动游戏.package`、`关闭阴阳师.package` | 渠道身份。`关闭阴阳师`（StopApp）框架直接生效；`启动游戏`（DirectHit）框架会丢弃，由引擎直读文件后显式投递（见 §3） |
| 渠道专属节点 | 华为 `关闭华为更新提示`；应用宝 `应用服-QQ登录`、`qq登录-同意登录` | base 里没有，只在渠道层定义 |
| next 链挂载 | 覆盖 `启动游戏-跳过动画.next` | 专属节点通过这条链进入启动流程 |

**三条硬规则**（探针会自动检查）：

1. **绝不用渠道层覆盖「启动游戏」的 next** —— 那会整条替换掉 base 的
   `next=[启动游戏-跳过动画]`，开场动画环节直接消失。专属节点应挂到
   `启动游戏-跳过动画` 的 next 上。
2. **`关闭阴阳师` 的 package 必须是纯包名** —— 它是 `StopApp`，走 `am force-stop`，
   带 `/activity` 会关不掉游戏。
3. **`package` 是唯一允许显式重复 base 同值** 的字段（渠道身份声明，显式比隐式清晰）；
   其它字段与 base 完全相同会报「冗余声明」。

## 2. 重构前发现的真实缺陷（都已修复）

用 `MaaResourceGetNodeData` 对原资源包逐渠道核对，发现：

| 缺陷 | 影响 | 修复 |
|---|---|---|
| 华为/应用宝覆盖的是 `启动游戏.next`，而 base 后来新增的 `启动游戏-跳过动画`（RandomTouch 跳开场动画）不在它们的链上 | **这两个渠道服永远不跳开场动画**，只能干等 | 专属节点改挂 `启动游戏-跳过动画.next`，`启动游戏` 保持 base 不动 |
| vivo 的 `关闭阴阳师.package` 写成 `com.netease.onmyoji.vivo/com.netease.onmyoji.tag0`（带 activity） | `am force-stop` 失败，**关不掉游戏** | 改为纯包名 `com.netease.onmyoji.vivo` |
| 华为链多一项、应用宝链少两项（`关闭广告-模板匹配`、`客户端更新提示处理`） | 渠道行为差异，无法判断是否有意 | **保持上游行为不变**（只修载体），差异在 `probe channel` 输出中可见，待实测后再定 |
| OPPO/vivo 缩进 10 空格、部分渠道冗余声明 `recognition: DirectHit` | 可读性差 | 统一 2 空格缩进 + 只写差异字段 |

## 3. `package` 为什么必须由引擎直读文件

框架规定 `package` 只在 `action` 为 `StartApp`/`StopApp` 时合法。base 的 `启动游戏`
是 `DirectHit`（桌面端语义：游戏已经在跑，脚本不去启动进程），所以渠道层写的
`启动游戏.package` 会被框架当**未知字段丢弃**——`MaaResourceGetNodeData` 里读不出来，
这就是 P3.1 验死结论「渠道包读出一字不差」的根因。

P3.5 的解法：

- **资源侧**：渠道层继续把 package 写在 `启动游戏` / `关闭阴阳师` 节点上
  （PI 协议兼容，MXU 交叉加载也不受影响）；
- **引擎侧**：`ChannelLayerResolver.ResolvePackages(chain)` **直读文件**取包名
  （后加载的渠道层覆盖 base；纯 base 资源集回落到 base 的 `关闭阴阳师.package`）；
- **运行时**：Adb 控制器下由执行链显式调 `MaaControllerPostStartApp` /
  `MaaControllerPostStopApp`（新增绑定，`MaaControllerApps` 统一封装）；
  Win32 控制器**不支持**这两个操作，返回 `Invalid`，调用方不必按控制器类型分支。

## 6. 使用

```powershell
MaaYys.P1Probe.exe channel                 # 静态拆出每个资源集的渠道层差异
MaaYys.P1Probe.exe channel --verify        # 逐个资源集真实加载 + 框架侧核对
MaaYys.P1Probe.exe channel --set 华为渠道服 --verify
```

给渠道层加一个新渠道的步骤：复制任一 `resource_pack/<渠道>/` 目录 → 改 `package` →
在 `interface.json` 的 `resource[]` 里加一条 `["./resource_pack/base", "./resource_pack/<新渠道>"]`。
不要复制 base 的完整节点，渠道层只写差异。
