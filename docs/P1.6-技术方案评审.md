## 1. 决策一：绑定方式 —— 自研 P/Invoke（`MaaYys.Engine.Native`）固化

| 方案 | 说明 | 评估 |
|---|---|---|
| **A. 自研 P/Invoke（现状）** | 手写 `DllImport` + `DllImportResolver` + `SafeHandle` | ✅ **选定** |
| B. 官方 NuGet 绑定 `Maa.Framework` | 社区维护的 C# 绑定包 | ❌ 版本滞后于 beta，且对 v5.15 Tasker 中心 API、AgentClient 覆盖不完整；引入第三方封送行为不可控 |
| C. C++/CLI 中间层 | 用 C++ 包装后供 C# 调用 | ❌ 额外工程 + 混合模式程序集，构建复杂度高，收益不抵成本 |

**结论理由**
1. P1.2–P1.5 全链路（Resource / Tasker / Controller / Toolkit / AgentClient）在自研绑定下已全部跑通，含 v5.13 → v5.15.0-beta.1 的一次无损升级（头文件一致，绑定层零改动）。
2. 需要频繁访问扩展点（自定义控制器、AgentClient、StringListBuffer），自研层可控性最好。
3. 运行库随仓库分发（`third_party/maafw/`），不依赖 NuGet 审核与版本对齐。

**固化约束（P2 起强制）**
- 所有 `DllImport` 只允许出现在 `src/MaaYys.Engine/Native/`：`MaaFrameworkApi.cs`（声明）、`MaaDef.cs`（常量/枚举）、`MaaHandles.cs`（SafeHandle）、`NativeLoader.cs`（解析）。
- 字符串一律 UTF-8 手动封送；返回借用的缓冲区（如 `MaaStringListBufferAt`）不可直接当字符串读。
- 新增原生 API 必须同时在 `MaaYys.P1Probe` 增加一个可执行的验证入口（P2 后该职责迁入 `tests/`）。
- Engine 层不得向上暴露任何 `IntPtr` / 原生句柄；统一走托管包装类。

## 2. 决策二：agent 语言与版本 —— Go 1.25 + `maa-framework-go/v4`

| 项 | 结论 |
|---|---|
| 语言 | **Go**（与功能基准 MaaYYs 一致，19 个动作 + 2 个识别可直接参考移植） |
| 模块路径 | `github.com/MaaXYZ/maa-framework-go/v4`（**必须 v4**，v1.x 线最高 v1.7.0 不含 AgentServer 绑定） |
| 版本 | `v4.0.0`（MaaYYs v3.13.6 的 agent 实证为 `v4.0.0-beta.12`，已用 `go version -m` 核对） |
| SDK | Go ≥ 1.25.0；本地 SDK 1.24.12 时由 toolchain 机制自动下载，构建脚本须固定 `GOTOOLCHAIN` 行为并在 CI 显式安装 1.25 |
| 通信 | `MaaAgentClient.CreateTcp(port)` → 拉起 `agent.exe <port> --libdir <maafw目录>` |

**固化约束（P4 硬性，违反即崩溃）**
1. **调用顺序**：`BindResource` 必须在 `Connect` **之前**（否则框架报 `resource is not bound` 拒绝握手）。
2. **销毁顺序**：`Disconnect` → 释放 AgentClient → 释放 Resource（Resource 早于 Disconnect 销毁会触发 `0xC0000005`）。
3. `MaaStringListBufferAt` 返回借用指针，需再经 `MaaStringBufferGet` 取 `char*`。
4. agent 子进程由 GUI 托管：启动拉起、心跳存活检测、退出回收、异常重启。

## 3. 决策三：P2 输入架构 —— 混合输入 + FramePool 截图

### 3.1 截图
- **默认 `FramePool`**；`CreateWithFallback` 依次尝试「首选 → FramePool → PrintWindow」，出现连接失败 / 空图 / 全黑 / **黑边 >10%** 时自动回退并输出诊断。
- 坐标映射：截图像素 → 客户区按比例映射，FramePool 下比例成立；**禁止再做 ×1.25 之类的手工修正**（那是 PrintWindow 黑边时代的补偿，叠加会双倍偏移）。
- 进程必须声明 **PerMonitorV2 DPI 感知**（`Program.cs` 已设，WPF 工程需在项目/清单层面同等声明）。

### 3.2 输入分层（核心架构决策）
| 层 | 场景 | 策略 |
|---|---|---|
| 场景层 / 主界面（庭院） | 打开面板、点主界面按钮 | **必须 `SetForegroundWindow` 后点击**，后台消息无效（10 组对照实测） |
| 二级面板层 | 面板内按钮、列表、关闭 | **后台消息点击**即可生效（实测关闭按钮、添加按钮均成功） |

**执行约定**
- 默认鼠标方式：`SendMessage`（P1.4 实测生效）；设置项暴露 `SendMessage / PostMessage / PostMessageWithCursorPos / Seize` 供用户切换（对标 MAA 连接设置）。
- 「切前台」只在**打开新面板**这一刻做一次，面板打开后全程后台操作，尽量不抢用户焦点。
- 全流程：截图 → 识别 → 若需打开面板则前台点击一次 → 面板内后台点击 → 识别确认。

## 4. 决策四：目录与编码规范（P2 起生效）

```
MaaYSS/
├── interface.json              # PI V2 入口（仓库根）
├── src/
│   ├── MaaYys.App/             # WPF GUI（P2.1 新建）：Views / ViewModels / Services / Themes
│   ├── MaaYys.Engine/          # 引擎封装：Native/ + 托管包装
│   └── MaaYys.P1Probe/         # P1 探针，P2 后冻结，P3 起由 tests/ 取代
├── agent/                      # Go agent（main.go / actions/ / recognitions/，P4 拆分）
├── resource/
│   ├── base/{pipeline,image,model}/    # 通用资源
│   └── <渠道>/{pipeline,image}/        # 官方/taptap/bilibili/huawei/tencent/OPPO/vivo 覆盖层
├── tasks/                      # 29 个任务定义 JSON
├── docs/                       # 规划文档 + reference/（官方 Schema）
└── third_party/maafw/          # MaaFramework 运行库（不入 git）
```

**命名约定**
- C#：项目/类型/方法 PascalCase，私有字段 `_camelCase`；WPF 视图 `XxxView.xaml` + `XxxViewModel.cs`。
- Go：包名小写单数；动作注册名 PascalCase（与 pipeline 中 `custom_action` 名一致）。
- 资源文件：移植部分**沿用 MaaYYs 原名**保证可比对；新增部分用小写英文 + 连字符。
- 配置：`interface.json` 走 PI V2 字段名；应用配置键名对齐 MAA `gui.new.json` 语义（便于对照与迁移）。

## 5. 决策五：配置存放与工程参数（P2 输入）

| 项 | 结论 | 说明 |
|---|---|---|
| GUI 框架 | **WPF**（.NET 9-windows） | 流程表既定；对标 MAA 的明暗主题、导航、托盘均可实现 |
| 应用配置位置 | 程序目录 `config/gui.json`（便携优先），缺失时回退 `%LOCALAPPDATA%/MaaYys/` | 便携部署与 MaaYYs 习惯一致；P2.6 实现导入导出/迁移 |
| 运行库加载 | `third_party/maafw/`，`NativeLoader` 优先按此路径解析 | 与打包目录一致 |
| 架构 | x64；P8 CI 增加 arm64 | WPF 与目标桌面端均为 x64 |

## 6. 遗留风险与行动项（带入 P2–P4）

| # | 风险 / 待办 | 落到 | 行动 |
|---|---|---|---|
| R1 | 主界面点击依赖前台，长时间运行会抢焦点 | P2.2 / P5.3 | 引擎层提供 `EnsureForeground()` 开关，默认开启，设置项可关（关闭后主界面操作可能失败） |
| R2 | 不同桌面端版本/皮肤下后台消息有效性未知 | P3 / P8.2 | 兼容性矩阵逐版本登记；失败时自动升级为前台点击 |
| R3 | Go toolchain 需联网下载 1.25 | P4 / P8.3 | CI 预装 Go 1.25；离线构建文档说明 |
| R4 | 渠道服资源分层与热重载 | P2.5 | 资源切换不重启进程，按 `resource[].path` 顺序加载、后加载覆盖先加载 |
| R5 | 截图黑边判据阈值 10% 需更多样本 | P2.3 | 阈值配置化，记录每次截图黑边测量值到日志 |
| R6 | AgentClient 与 Resource 生命周期耦合，易误用 | P2.2 | 引擎层封装 `MaaYysEngine` 统一托管生命周期，禁止上层直接持有原生句柄 |

## 7. 评审结论

P1 六项任务全部完成，技术方案冻结：

1. 绑定方式：自研 P/Invoke（Native 目录集中管理）。
2. agent：Go 1.25 + maa-framework-go/v4 v4.0.0，遵守调用/销毁顺序约束。
3. 输入架构：FramePool 截图 + 混合输入（开面板前台一次、面板内后台）。
4. 目录规范与配置位置按第 4/5 节执行。

**P2 按流程表 2.1 → 2.6 顺序启动。**
