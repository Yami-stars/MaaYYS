## 1. 交付内容

设置页新增**第六个分类「通知」**（左侧导航：连接 / 启动 / 运行 / 通知 / 日志与缓存 / 关于）。

- **应用内通知**：
  - 卡住超时（秒，0 = 关闭）：运行期间超过该时长**没有任何任务状态变化**就弹应用内 Toast「任务可能卡住了」。
  - 提醒间隔（分钟，0 = 关闭）：运行期间每隔 N 分钟弹一次「仍在运行」。
  - 这两条都**只提醒、不打断任务**——和「运行」页的停滞超时（判卡死并停机）是两回事。
- **外部通知（Webhook）**：
  - 总开关 + 三个触发条件（队列完成 / 队列失败 / 检测到卡住）。
  - 通道配置：Webhook 地址、方法（POST/PUT）、Content-Type、自定义请求头（多行 `Key: Value`）、请求体模板。
  - 模板支持变量 `{title}` `{message}` `{time}` `{trigger}`，页面有「模板预览」实时看会发什么。
  - 「发送测试消息」按钮：走和用户点界面完全相同的 `NotifyAsync` 路径，绕过触发门控直接发一次。

## 2. 架构

```
InstanceWorkspace.Notifier (App/Services/NotificationService)
   ├─ RaiseToast → ToastRequested 事件 → MainWindow 订阅 → 4 秒自隐横幅
   └─ Engine.Notification.NotificationService.SendAsync  → HttpClient 真实发请求
QueueRunService（运行期）
   ├─ 启动 15s 定时器：卡住超时 / 提醒间隔判定
   └─ 收尾：完成/失败 → 应用内 Toast + 外部 Webhook（按触发门控）
```

- **即时生效**：设置项无保存按钮，写入 `config/maayys.json` 的 `settings.notification` 段后立即广播（与 P6.2 同一套「同一实例引用」策略）。
- **失败降级**：外部 Webhook 任何网络/HTTP 异常都只记日志、返回 `NotificationResult.Failed`，**绝不抛到调用方**——通知是锦上添花，不能拖死队列。
- **提醒只弹应用内**：提醒间隔走 `sendExternal:false`，不会误发外部请求（即使外部通知开着）。

## 5. 设计取舍

- **外部通知只做 Webhook 一个通道**：Webhook 用 HTTP POST，本机就能用本地监听端真实验收，命中 P6.3 的验收标准（「外部通知可真实收到测试消息」）。Telegram / 邮件 / 企业微信 / 飞书 / 钉钉 等多通道属于后续批次——不做假开关。
- **卡住检测独立**：`notification.stuck_timeout_seconds` 只弹提示不打断；与 `run.stall_timeout_seconds`（停机）解耦，可独立开关。
- **提醒不发外部**：避免「每隔 N 分钟给你邮箱发一封信」的骚扰，提醒本就是轻量的应用内提示。
