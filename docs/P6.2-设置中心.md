# P6.2 设置中心-系统类 · 验收报告

> 对应 `docs/MaaYys-开发流程表.md` 第 2 节 6.2 行。
> 验收条件：**每个设置项改动即时生效并持久化**。

---

## 1. 交付概览

设置页从「一页滚到底」改成**左侧分类 + 右侧内容**的五分类结构（对标 MAA 设置中心）：

| 分类 | 解决什么问题 | 主要设置项 |
| --- | --- | --- |
| 连接 | 连不上 / 画面不对 / 点不动 | 截图方式、鼠标方式、键盘方式、预览帧率、默认窗口正则、「应用到全部实例」 |
| 启动 | 程序开了但游戏没开 | 前置程序路径/参数/等待秒数、连接时自动启动、**开机自启**、静默启动 |
| 运行 | 跑一半卡住 / 不知道会不会自愈 | 停滞超时、失败重试、重试间隔、失败即停、单任务时长上限、定时轮询间隔、防休眠、前后置脚本、完成后动作 |
| 日志与缓存 | 崩溃后想回看 / 磁盘占用 | 内存日志（时间格式、保留条数、节点事件、缩略图）、**日志落盘**、图片缓存清理、资源整理状态 |
| 关于 | 「资源没更新」「配置改了没生效」 | 版本与四类路径（程序目录 / 配置 / 实例 / 资源）、配置是否已落盘 |

全部设置项**没有「保存」按钮**：改动即写 `config/maayys.json` 并广播，各消费方（执行器 / 定时器 / 日志 sink / 窗口）当场按新值工作。

## 2. 数据模型

新增 `MaaYys.Engine/Config/AppSettings.cs`（四组，JSON 顶层 `settings` 段）：

```
settings
├── connection     截图/鼠标/键盘方式、预览帧率、默认窗口正则
├── startup        前置程序路径/参数/等待秒数、自动启动、开机自启、静默启动
├── run            停滞超时/重试/间隔/失败即停/时长上限/轮询间隔/防休眠/完成后动作/前后置脚本
└── file_log       落盘开关、目录、单文件上限(MB)、保留份数、最低级别
```

每条都有安全默认值；`Sanitized()` 把越界值与非法枚举夹回合法区间（负数超时、`max_retries=99`、
截图方式写了不存在的名字、`after_completion=reboot` 都只会回落默认，不会让程序起不来）。
`ConfigurationStore` 新增 `Settings`（同一实例引用）+ `UpdateSettings()`（夹取 → 落盘 → 广播），
与 P5.5 的 `LogOptions` 同一套语义。

`FileLogSettings` 放在 `MaaYys.Engine.Logging` 命名空间（与 `LogOptions` 同家），避免
Config ↔ Logging 的命名空间互相引用。

## 3. 生效链路（关键设计）

| 设置 | 谁消费 | 怎么做到「即时」 |
| --- | --- | --- |
| 执行策略（超时/重试/失败即停/时长） | `QueueRunService` | 每次 `RunAsync` 从设置构造 `ExecutionOptions`；执行器按**策略签名**比对，变了就在下次启动时重建（运行中的队列不被中途改策略） |
| 定时轮询间隔 | `TimerRunner` → `TimerScheduler` | 改完调 `ApplyInterval()`：正在跑就 Stop+Start 按新周期重启 |
| 日志落盘 | `FileLogSink`（挂在 `LogBuffer.Mirror` 上） | sink 持有 `FileLogSettings` **同一实例**，每次写入都读开关/级别；关掉即刻停写并关闭句柄 |
| 完成后动作 | `QueueRunService.FinishRun` | 从设置读；只在 `ExecutionOutcome.Completed` 触发（停止/暂停/失败都不触发） |
| 防休眠 | `SleepGuard`（`SetThreadExecutionState`） | 队列开始时按设置 Acquire，结束时释放；不用改电源计划 |
| 开机自启 | `AutoStartService` | 开关即时写/删 `HKCU\...\Run` 下的 `MaaYys` 值；程序启动时 `Sync()` 修正被移动过的路径 |
| 前置程序 | `LaunchService` | 连接时窗口找不到 → 启动并**轮询等窗口出现**（不是死等固定秒数），窗口一出现立刻重试连接 |
| 连接方式 | 实例定义 | 设置里是全局默认值；「应用到全部实例」批量写回实例清单 |

**完成后动作从任务页搬到了 `QueueRunService`**：P6.1 里它是 `TasksViewModel` 的私有逻辑，
定时触发的队列跑完不会执行动作，而且手动跑一次可能被执行两遍。现在只有一处实现。

## 4. 顺带修掉的三个全局缺陷

1. **TextBox / ComboBox 在暗色主题下是系统白底**
   WPF 默认模板不认主题色：`TextBox` 还能靠 TemplateBinding 上色（加隐式样式即可），
   `ComboBox` 的 Aero 模板颜色是硬编码渐变 → 重写模板（背景 + 自绘箭头 + Popup 列表 + ComboBoxItem 高亮）。
2. **CheckBox 是「白方块 + 浅字」**
   P5.5 只补了 `Foreground`，方框仍是系统白底。这次自绘方框：未选中空心、选中显示强调色对勾，
   文字用 `TextElement.Foreground` 显式传递（ContentPresenter 不继承）。
3. **`DisplayMemberPath` 在自定义模板下失效**
   换成 ItemTemplate 的三处：顶栏实例下拉、任务选项 select 下拉、任务页实例下拉
   （否则选中项会显示成 `MaaYys.App.ViewModels.InstanceViewModel`）。

另外修掉一个潜伏问题：`InstanceWorkspace` 创建 `InstanceViewModel` 时**没传 `LogOptions`**，
导致引擎日志管线用默认策略 —— 日志页改时间格式/容量对引擎侧无效。现已传配置里的同一实例。

## 5. 有意不做的两项（避免假开关）

| 流程表原条目 | 决定 | 原因 |
| --- | --- | --- |
| 连接设置-静音 | **不做** | MaaFramework 的 Win32/ADB 控制器都没有音量接口（`MaaFrameworkApi` 里 grep 不到任何 mute/volume）。做出来只会是个不生效的开关，需要静音请用系统音量。 |
| 运行设置-区服 | **不做** | 资源侧没有区服概念（登录由用户手动或 agent 处理），没有任何地方消费这个值。 |

## 7. 新增调试参数

| 参数 | 说明 |
| --- | --- |
| `--settings 分类` | 切设置页第二级分类（`连接` / `启动` / `运行` / `日志与缓存` / `关于`） |
| `--tool 分类` | 切小工具第二级分类（`定时任务` / `运行日志` / `设备探测`，也吃下标） |
| `--set-setting "分类.属性=值"` | 通过设置子页 VM 的属性 setter 赋值（可重复）——走的是与用户点界面**完全相同**的路径，因此能验证「改完立刻落盘」 |
| `--silent` | 开机自启时使用：窗口最小化启动 |

> `--set-setting` 用了反射，只在 `--screenshot` 调试分支里生效，生产路径不经过它。

## 8. 已知限制

- **前置程序的窗口等待依赖 MaaToolkit**：探测失败时按「没找到」处理（不会误判成功），
  但也就不会提前结束等待，只能耗满等待秒数。
- **防休眠未经长跑验证**：代码路径在队列开始/结束各调一次 `SetThreadExecutionState`，
  真正「跑 2 小时机器不睡」需要实机挂机验证（归 M4 长跑验收）。
- **前后置脚本只测了路径与存在性分支**：`.bat/.cmd/.exe` 走 `cmd /c`，`.ps1` 未单独处理
  （需要 `powershell -File`），文档里没写成支持。
- **连接设置是「新建实例的默认值」**：已有实例不会自动跟随，需要点「应用到全部实例」批量下发。
- **顶栏实例下拉仍只管切换**：增删仍在「多实例」页。
